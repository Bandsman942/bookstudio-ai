# BookStudio AI — v0.43.0-alpha (candidate, non déployée)

## Contenu

**BS-008f/BS-009c [#199](https://github.com/Bandsman942/bookstudio-ai/issues/199)** — pérenniser la hiérarchie des parties de l'ouvrage dans les versions figées et ses exports.

- Les **nouveaux snapshots v2** enregistrent titres/IDs de parties, rattachement et ordre historiques de chaque chapitre, révision et empreinte. Le hash immuable protège la structure contre la corruption et les modifications ultérieures. Tous les anciens snapshots v1 restent lisibles sans réécriture.
- **Restaurer comme nouvelle édition** à partir d'un snapshot v2 recrée des parties avec des identifiants indépendants et y affecte les nouveaux chapitres dans l'ordre d'origine, sans toucher à l'ancien contenu ; les v1 se restaurent toujours en structure plate.
- Les exports d'un snapshot structuré présentent une **table des matières parties/chapitres** dans les DOCX, PDF et Markdown ; liens internes DOCX, en-têtes de parties, échappement XML et police Unicode PDF. Le sommaire est fondé sur **l'état figé**, même si des parties sont renommées ou déplacées ensuite.
- Test de compatibilité des hash anciens, intégrité v2, regroupement, rendu Word/PDF 13 chapitres et HTTP E2E PostgreSQL avec refus ACL/CSRF/concurrence. Aucune migration SQL, ni nouvelle variable, ni activation IA/ClamAV.

## Risques

- **NON DÉPLOYÉE** : CI complète au SHA de la PR et **`E2E v0.43.0-alpha BON` propriétaire** sont requis avant snapshot Neon de production, fusion main et Vercel production uniquement.
- Les titres H1–H3 internes restent dans les exports, mais ne figurent pas encore dans la **table des matières générée** (prochain lot). Le PDF n'invente pas des numéros de page ; le DOCX utilise des liens internes et non des numéros fixes.
- Le bouton historique « Restaurer les textes » dans la même édition n'est **pas** une restauration de structure ; pour les parties, utiliser **Restaurer comme nouvelle édition**. Les anciennes versions v1 ne disposent pas d'informations sur les parties.
- La version v0.42 du logiciel ne reconnaît pas les nouveaux manifests v2. En cas de rollback, conserver la base et les snapshots, et rétablir une version compatible pour les consulter. Contrôle E2E import/export/restauration indispensable.
- ClamAV sur serveur dédié non installé et indicateurs antivirus non activés. Aucun service IA externe sollicité.
