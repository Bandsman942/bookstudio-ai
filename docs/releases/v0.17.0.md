## Contenu de la version

### BS-010a2 (#120) — Adaptateur antivirus ClamAV sur worker isolé

Le module `apps/worker-documents/source_guard.py` traite un fichier local déjà
matérialisé dans un environnement privé, sans traverser les fonctions Vercel.
Il utilise une copie exclusive mode `0600`, SHA-256 streaming et contrôles de
taille/empreinte, puis exécute `/usr/bin/clamscan` sans shell, avec timeouts,
capture de l'identité/version et refus explicite en cas d'indisponibilité.
Les options `--alert-exceeds-max=yes` et `--alert-encrypted=yes` empêchent de
prendre pour un fichier sain un conteneur dépassant les plafonds ou chiffré.
Une base quotidienne ClamAV absente ou dont les fichiers datent de plus de 48 h
entraîne `SCAN_UNAVAILABLE`, jamais `SCANNED_CLEAN`.
Après analyse, le contenu du fichier temporaire est revérifié ; toute altération
annule le verdict positif. Les messages ne divulguent ni nom de source ni texte.

Tests unitaires : fichiers propres simulés, signature infectée simulée, erreur
du moteur, timeout, absence de scanner, mauvais SHA/size, symlinks, trop gros
fichier, copie modifiée. Test réel clean/EICAR opt-in :
`docs/qa/E2E-ISOLATED-SOURCE-GUARD-0.17.0.md`.

Le test HTTP E2E compare dorénavant `/api/version` aux valeurs de `release.json`
pour éviter un échec artificiel à chaque changement de version.

## Risques et limites

- **Ce code n'est pas encore un service antivirus opérationnel.** La CI utilise
  des retours simulés ; pour annoncer une protection, il faudra un moteur réel,
  des signatures à jour, un worker isolé supervisé et l'E2E clean/EICAR.
- Aucune communication Supabase/Neon ni signature d'attestation : les verdicts
  produits localement ne modifient pas `SourceSecurityRecord` et ne sauraient
  lever la restriction du mode strict.
- Quarantaine physique, accès signé de courte durée, idempotence/retry, contrôle
  d'identité du worker et sauvegarde/restauration des binaires restent ouverts
  dans #104. Ne pas exposer de manuscrits clients à ce composant non intégré.
- La production v0.16.0-alpha reste inchangée pendant la revue et la recette.
