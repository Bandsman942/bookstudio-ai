# BOOKSTUDIO AI — v0.30.0-alpha (production privée vérifiée le 8 novembre 2026)

## Contenu

P0 BS-008d #158, suites #9 et #6 : historique paginé des révisions d'un chapitre dans le Studio, auteur/date/numéro, aperçu privé en texte brut à la demande et restauration ciblée **append-only** : le texte d'une révision ancienne est copié dans une **nouvelle révision**, aucune ancienne révision n'est écrasée. Statut du livre retourné à DRAFT ; audit auteur/fromSequence/toSequence sans prose.

API privées : `GET /api/v1/books/{bookId}/chapters/{chapterId}/revisions`, `GET /.../revisions/{sequence}`, `POST /.../revisions/{sequence}` ; authentification et membership, OWNER/EDITOR sur écriture, confirmation RESTORE_CHAPTER_REVISION, Origin CSRF, expectedRevision, verrou de livre FOR UPDATE dans transaction Serializable, revalidation de l'édition courante, erreurs 400/401/403/404/409/413/422/503. Historique de l'ancienne édition consultable via Éditions, jamais modifiable par cette nouvelle route. Pagination 20/50, pas de texte dans le listing.

UI FR/EN : bouton Historique en tête du Studio, modale viewport à portée du clavier/mobile, liste avec dates et auteurs, aperçu plein texte, seconde confirmation, impossibilité de restauration si autosave/brouillon local non résolu. Après succès, nouvelle clé de montage du Studio selon la révision enregistrée ; toast personnalisé. Tests unitaires et HTTP E2E multi-tenant, nouvelles révisions sans perte, conflits, passage à une autre édition, documentation et release gates avant publication.

## Risques

- **Production vérifiée** : E2E propriétaire `v0.30.0-alpha BON`, CI GitHub #216 SUCCESS sur le SHA de la PR `2743e255a5ccabfd9bc1dc1163f808275de9b6ce`, snapshot Neon `snap-hidden-mud-bfw2ewji` avant fusion, main `b46c21976c247ea450a2edbafee02e13e8afbeea`, Vercel `dpl_8n81aoY1d8QwQd88YgjDqLaY1wQ1` READY, `/api/health` et `/api/version` HTTP 200 le 8 novembre 2026 à 17:49 UTC. Preuves complètes : `docs/deployments/2026-11-08-v0.30.0-alpha.md`.
- L'aperçu de texte historique ne reproduit pas les styles riches de Word. La restauration copie le JSON document structuré, mais ne réécrit pas les commentaires, les sources ni les snapshots.
- Les historiques de centaines ou milliers de révisions sont paginés ; un aperçu individuel est chargé en entier sur demande et peut être plus lent sur une connexion très faible.
- Aucune migration Prisma, aucune variable secrète, pas de scanner antivirus : ClamAV isolé non installé, flags OFF. Les anciens hash des révisions n'ont pas été recanonisés après stockage JSONB.
- L'autosauvegarde du chapitre peut rencontrer 409 si un autre utilisateur a restauré une révision ; résoudre manuellement, ne jamais écraser. L'usage de DRAFT après restauration est volontaire pour invalider les validations antérieures.
- P0 BS-008 #9 et BS-005 #6 restent ouverts pour leurs critères non livrés (diff mot à mot, suggestions, reprise complète), ainsi que sécurité ClamAV.
