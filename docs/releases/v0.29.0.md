# BOOKSTUDIO AI — v0.29.0-alpha (production privée vérifiée le 8 novembre 2026)

## Contenu

Issue #155 / P0 BS-008c (parent #9) : nouvelle opération de **restauration conservatrice de snapshot historique vers une édition indépendante** depuis Versions & historique, sans détruire aucune édition existante. La copie porte uniquement sur les chapitres et révisions listés dans le manifeste de la version nommée et produit des IDs neufs, une révision 0 et un statut DRAFT ; aucune provenance de source, aucun commentaire ou validation n’est recopié. Elle fonctionne même lorsque le snapshot précède plusieurs éditions ou concerne un chapitre depuis supprimé de l’édition source.

API `POST /api/v1/books/{bookId}/snapshots/{snapshotId}/restore-as-edition` : session, RBAC OWNER/EDITOR, protection CSRF, préconditions sur le livre et son édition courante, transaction Serializable, validation du manifeste et des signatures des révisions historiques, audit non sensible, plafonds 500 chapitres / 20 MiB. L’API des versions indique le numéro d’édition source lorsque disponible. Correction simultanée du risque d’autosauvegarde d’un ancien onglet sur un chapitre devenu historique : verrou de ligne + revalidation de l’édition dans la transaction.

UI FR/EN, nouvelle action et confirmation explicite distincte de la restauration *dans l’édition courante*, toasts circonstanciés, actualisation liste d’éditions, compatibilité mobile/desktop, réseau faible. Tests unitaires de la copie, E2E HTTP avec refus négatifs et conservation des anciennes éditions, contrôle documentaire dans CI.

Journal `docs/deployments/2026-11-08-v0.29.0-alpha.md`.
- Cette copie directe est limitée à **500 chapitres et 20 MiB** ; pas de traitement asynchrone massif, pas de fusion intelligente entre éditions, ni de comparaison caractère par caractère.
- Le contrôle d’intégrité compare le manifeste signé avec les empreintes de révision enregistrées : les anciens hash ont été calculés avant persistance JSONB ; aucune réempreinte canonique rétroactive ne peut être revendiquée. L’intégrité de la sauvegarde de plateforme doit rester vérifiée indépendamment.
- Les modifications **non sauvegardées** dans les onglets ne font pas partie d’un snapshot. Les autres onglets d’écriture peuvent recevoir 409 et doivent recharger.
- **ClamAV dédié pas installé** : aucun scan antivirus affirmé ni nouvelle activation de flags. Les tickets #104/#126/#131/#133 restent ouverts.
- Pas de migration, nouvelle variable ou changement d’API DTSC. La sécurité opérationnelle de production publique reste conditionnée aux P0 non terminés.
