# BookStudio AI v0.20.0-alpha — candidate NON FUSIONNÉE

## Contenu

La tranche #129 de #126 prépare une **file de traitement durable** dans Neon pour les sources déjà confirmées par Supabase. Le modèle `SourceScanJob` conserve identité livre, nom de stockage, génération unique et taille/type déclarés ; il ne copie aucun manuscrit.

À chaque confirmation, `SourceSecurityRecord.sourceGeneration` change, les travaux précédents sont invalidés, et l'ancien verdict est remis à `UNSCANNED`. L'enregistrement d'un nouveau travail et le statut `QUEUED` sont **optiques** via `BOOKSTUDIO_SOURCE_SCAN_QUEUE_ENABLED=true`. Le flag est **OFF** par défaut et NE DOIT PAS être activé sans un service worker déployé et correctement supervisé.

Les demandes sont limitées à 30 par ouvrage et par heure sous le flag, sans émission d'une déclaration `SCANNED_CLEAN` ni publication d'une interface de validation antivirus. Les suppressions de sources annulent les travaux non achevés sans effacer l'audit.

## Risques

- Aucune analyse réelle n'est encore exécutée ; pas de réservation de job par worker, pas de preuve M2M, pas d'attestation des octets, pas de stockage en quarantaine et pas de backup autonome des données de Supabase.
- L'identité d'une génération protège contre les verdicts tardifs mais **ne suffit pas** à prouver l'immuabilité de l'objet source ; le futur worker devra vérifier le hash sur les octets récupérés et établir une preuve signée.
- Ne jamais activer le mode strict `BOOKSTUDIO_REQUIRE_SCANNED_SOURCES` avant la chaîne complète validée.
- E2E propriétaire `v0.20.0-alpha BON` + CI + snapshot Neon requis avant publication sur main, Preview désactivées. #104/#126 restent ouverts.
