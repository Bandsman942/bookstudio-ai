# BOOKSTUDIO AI — v0.33.0-alpha (candidate NON fusionnée / NON déployée)

## Contenu

Suite du cahier des charges BS-004 (#5), issue BS-004g **#167** : nouvelle action **Dupliquer ce chapitre…** depuis les menus contextuels de chapitres dans le sommaire et l'éditeur. L'utilisateur OWNER/EDITOR autorisé choisit un titre, puis un **nouveau chapitre indépendant** est ajouté à la fin de l'édition courante, avec ID neuf et révision 0. Son contenu structuré est issu **exclusivement de la dernière révision enregistrée du chapitre d'origine** ; aucun contenu n'est tronqué ni réécrit par l'IA. Les autres chapitres et le chapitre source demeurent inchangés, et le statut du livre retourne à Brouillon.

API POST privée `/api/v1/books/{bookId}/chapters/{chapterId}/duplicate` avec session, membership, CSRF Origin, confirmation forte, `operationId` UUID idempotent, `expectedEditionId`, `expectedRevision`, `expectedChapterUpdatedAt`, transaction Serializable et verrou sur la ligne livre. Refus précis 400/401/403/404/409/413/422/503 ; limite 500 chapitres actifs et 20 MiB par copie, sans conversion ni troncature. Même opération répétée donne 200 et le même ID de copie ; 201 pour la création. Audit sans prose. Aucun commentaire, snapshot, source Supabase/import, preuve de scan, permission ou ancienne version n'est copié.

UI FR/EN responsive mobile/clavier, état d'attente, confirmation explicitant les brouillons non enregistrés, contrôle anti-perte de l'éditeur avant navigation, toasts contextualisés et redirection vers chapitre nouveau. Tests unitaires de fidélité et limites, HTTP E2E PostgreSQL multi-tenant (autorisations, conflits et non-régression), docs complètes prépublication. Pas de migration ou variable nouvelle.

## Risques

- **CANDIDATE NON PUBLIÉE** : production demeure v0.32.0-alpha. Ne pas fusionner ou déployer avant GitHub CI SUCCESS dernier SHA puis validation propriétaire `E2E v0.33.0-alpha BON`. Snapshot Neon production **avant** fusion ; Vercel **main uniquement**, Preview OFF.
- Les brouillons locaux non enregistrés ne sont jamais repris ; l'interface avertit et bloque si possible la navigation depuis un éditeur sale.
- Le chapitre dupliqué est **en fin de sommaire**, sans déplacement automatique des chapitres existants ; réorganisation manuelle déjà disponible. Seuls les contenus récents de l'édition courante peuvent être copiés.
- Anciennes révisions, commentaires, snapshots, historiques d'import et objets Supabase **non copiés** ; statut DRAFT nécessite une nouvelle validation avant publication.
- ClamAV isolé non installé ; aucun objet ou attestation de sécurité n'est copié et aucun `SCANNED_CLEAN` inventé. Variables de scan/strict toujours OFF.
- Parents BS-004 et BS-005 ouverts pour exigences restantes ; pas de nouvelles migrations SQL.
