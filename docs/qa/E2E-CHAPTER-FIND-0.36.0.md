# E2E v0.36.0-alpha — Rechercher/remplacer dans le chapitre (#176)

**Candidate NON déployée.** Ne pas fusionner sur main ou publier Vercel avant GitHub CI SUCCESS au dernier SHA **et** validation propriétaire `E2E v0.36.0-alpha BON`.

1. Créer ou ouvrir dans le Studio un chapitre riche de plusieurs paragraphes, titres et segments en **gras**, *italique*, ainsi qu'un lien HTTPS. Enregistrer au moins une révision. Ajouter les termes « Été » et « été » plusieurs fois dans un même segment ainsi que « un » et « une » pour vérifier la recherche **littérale**, insensible à la casse et le refus d'utiliser le point `.` comme expression régulière.
2. Cliquer sur **⌕** dans l'en-tête du Studio. Le panneau doit rester visible sur ordinateur et Chrome mobile (320, 375, 768px), en clair et sombre ; le champ recherche reçoit le focus. Les raccourcis Ctrl/Cmd+F et Ctrl/Cmd+H doivent ouvrir respectivement la recherche et le mode remplacement.
3. Saisir « été » : vérifier le compteur des occurrences **du segment de texte**, puis les boutons Précédent/Suivant, Enter et Shift+Enter dans le champ, les sélections dans la page et la navigation circulaire. Activer **Respecter la casse** : seules les occurrences avec casse identique sont comptées.
4. Chercher un mot dont une moitié est en gras et l'autre en texte normal : il n'est **pas remplacé**, car la version initiale ne recherche pas à travers deux nœuds avec styles distincts. L'avertissement est visible et évite toute perte silencieuse de formatage. Les mots entiers dans un nœud gras ou lien restent modifiables sans ôter leur marque.
5. Passer en **Remplacer…**, entrer une substitution plus courte puis plus longue, vérifier **Remplacer cette occurrence** : une occurrence change, les autres restent identiques ; gras, italique et liens non concernés sont intacts. Vérifier une substitution par chaîne vide (suppression du seul terme) puis Ctrl/Cmd+Z.
6. Sélectionner **Prévisualiser tout remplacer**. L'interface affiche le **nombre exact** de substitutions. Sans confirmation, rien n'est modifié. Après confirmation, les occurrences trouvées sont changées dans **une seule transaction** ; un seul Ctrl/Cmd+Z restitue le chapitre avant l'opération. Les toasts précisent « appliqué localement », puis l'état passe par l'autosauvegarde existante jusqu'à **Enregistré**.
7. Modifier manuellement le texte **entre la prévisualisation et la confirmation** : la confirmation doit refuser cette version obsolète, ne pas appliquer partiellement la transaction et demander de relancer la prévisualisation.
8. Ajouter au moins 501 occurrences du même terme : le panneau indique « Plus de 500 résultats », désactive `Remplacer tout` et propose d'affiner la requête. Les 500 premiers peuvent être parcourus sans jamais prétendre que la liste est exhaustive.
9. Dans un document proche de la limite **2 MiB** de l'éditeur, tenter un remplacement qui la dépasserait : le résultat est refusé sans détruire le contenu ni le modifier partiellement. Un texte de substitution >1000 caractères ou comportant une rupture de ligne n'est pas accepté.
10. Tester lecteur REVIEWER/VIEWER : recherche/lecture disponibles, remplacement indisponible. Tester conflit de révision, erreur de sauvegarde, récupération locale en attente et mode hors-ligne : le remplacement est bloqué avec message compréhensible. À la récupération de la connexion, aucune substitution non approuvée ne doit se faire.
11. Fermer le panneau, changer de chapitre, revenir et contrôler que les changements sauvegardés sont présents, sans affecter les autres chapitres ou éditions. Tester mobile, clavier, lecteur d'écran et fenêtres de dialogue ouvertes.
12. Vérifier la **CI finale** : `pnpm release:check`, `pnpm chapter-find:check`, `pnpm ui:check`, `pnpm perf:check`, `pnpm test`, worker tests, HTTP E2E PostgreSQL, TypeScript/build. Les documents fonctionnels, conception, API (pas de route nouvelle), exploitation, QA, README, changelog, backlog et release doivent être **dans la PR avant publication**.
